# Сервер медицинского калькулятора

Fastify 5, TypeScript, Zod 4. Запуск из корня: `pnpm dev:api`. Адрес по умолчанию: `127.0.0.1:3001`. `API_HOST` и `API_PORT` переопределяют bind для контейнера. Проверка состояния: `GET /api/v1/health`. Документ OpenAPI из доверенных статических Zod-схем доступен после входа: `GET /api/v1/openapi.json`.

## Выбор хранилища

При заданном `DATABASE_URL` используется PostgreSQL, в том числе при `DEMO_MODE=true`. Без `DATABASE_URL` файловый адаптер допустим только с явным `DEMO_MODE=true`. Сочетание `NODE_ENV=production` и `DEMO_MODE=true` запрещено. Путь локального файла: `DEMO_DATA_PATH`, по умолчанию `.data/demo.json`.

Демонстрационные учетные записи создаются только в пустом хранилище при `DEMO_MODE=true`:

| Логин      | Пароль               | Роль                    |
| ---------- | -------------------- | ----------------------- |
| doctor     | doctor-demo-2026     | DOCTOR                  |
| pharmacist | pharmacist-demo-2026 | CLINICAL_PHARMACOLOGIST |
| clinical   | clinical-demo-2026   | CLINICAL_ADMIN          |
| admin      | admin-demo-2026      | SYSTEM_ADMIN            |

В штатном режиме пустая база требует `BOOTSTRAP_ADMIN_LOGIN` и `BOOTSTRAP_ADMIN_PASSWORD` длиной минимум 16 символов. Первый пользователь — системный администратор. Он создает клинического администратора; затем медицинская команда импортирует и утверждает контент. Пока активные клинические правила и реестр не опубликованы, клинические маршруты возвращают 503, а вход и административные маршруты доступны.

## Доступ и история

Пароли хранятся как scrypt-хэши с индивидуальной солью. Session cookie содержит случайный opaque token; в БД сохраняется только SHA-256. Cookie имеет HttpOnly, SameSite=Lax и Secure в production. Абсолютный срок сессии — 8 часов, idle timeout — 30 минут. Роль и блокировка читаются при каждом запросе. POST/PATCH требуют точный `Origin` из `APP_ORIGIN`; несколько адресов разделяются запятой. Production требует HTTPS origin. Вход ограничен 10 попытками за минуту на IP; reverse-proxy headers по умолчанию не считаются доверенными.

Врач видит собственные случаи. Клинический администратор и фармаколог читают другие случаи с аудитом. Системный администратор управляет пользователями, но не получает клиническую историю и не публикует правила. Редактировать и рассчитывать можно свой черновик. Каждая редакция и финальный расчет сохраняют отдельный snapshot; preview и финальный расчет используют одну доменную функцию. Feedback, история, аудит и опубликованные пакеты неизменяемы.

Экспорты CSV/XLSX содержат обезличенные факты, исходы, предупреждения, версии, хэши и feedback. CSV экранирует начало формул, XLSX записывает текстовые значения. Raw clinical payload не попадает в штатный журнал HTTP.

## Управление медицинским контентом

Поддерживаются `CLINICAL_RULESET`, `drug_registry`, `contraindication_ruleset`, `interaction_ruleset`, `dose_ruleset`. Therapy catalog и метаданные формы в 0.1.0 входят в канонический клинический пакет. Исходный DRAFT не становится опубликованным при запуске. Статусы DRAFT → IN_REVIEW/VALIDATED → PUBLISHED. Для публикации нужны роль CLINICAL_ADMIN, содержательная `approval_note` и успешно вычисленные golden cases.

Отдельные пакеты используют поля `version`, `status`, `provenance: {source, note?}`, `compatibility: {clinical_ruleset: "0.1.0"}` и `drugs` либо `rules`. Совместимость точная. Для подготовки зависимостей будущей версии можно указать уже опубликованный клинический пакет из inventory, даже если он еще не активен. Неподдержанные derived facts и включенные правила со статусом, отличным от VALIDATED, отклоняются. Переназначать существующий `drug_id` другому `normalized_code` нельзя.

Golden case: `{name, case:{nosology_code,facts,medications}, expected:{status,outcome,options?}}`. Для клинического пакета требуется покрытие всех активных нозологий. Для отдельных пакетов `expected.options` обязательно: safety явно проверяет `action`, дозирование — `dose_status: "ADJUSTED"` и `regimen`, реестр — `drug_name`. Каждое включенное правило должно сработать в trace хотя бы одного проверенного случая. Утверждение пакета не снимает необходимость медицинской проверки исходных нормализаций и источников.

`POST /api/v1/admin/packages/activate-set` принимает `{package_ids:["uuid", ...]}`: не более одной опубликованной версии каждого типа. Все изменения и аудит фиксируются одной транзакцией после проверки итоговой совместимости. Это позволяет переключить клинический граф и его зависимости вместе; несовместимая отдельная активация возвращает 409 без частичной записи. Штатный расчет не использует исходные DRAFT safety/dose-массивы: без их активных публикаций эти компоненты недоступны, что отражается в доменных предупреждениях.
