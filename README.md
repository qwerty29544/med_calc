# Медицинский калькулятор · 0.1.0

Веб-приложение поддержки врачебного решения по шести нозологиям: хронический и острый бронхит, пневмония, обострение ХОБЛ, фарингит/тонзиллит, синусит. Реализация основана на предоставленных ТЗ и Rule Engine Contract 0.1.0.

**Поставляемый медицинский контент имеет статус DRAFT.** Приложение запускается для демонстрации и технической проверки. Медицинское утверждение исходных деревьев, схем, противопоказаний, взаимодействий и эталонных случаев выполняет медицинская команда. Исходные mock-правила не участвуют в лечении.

## Быстрый запуск на Windows

**Через Docker Desktop:** откройте `start-docker.cmd` двойным щелчком. Скрипт создаст локальный `.env.docker` со случайным паролем БД, соберет приложение, выполнит миграции, дождется готовности сервисов и откроет [http://localhost:8080](http://localhost:8080). Node.js на компьютере для этого варианта не нужен. Первая сборка загружает зависимости и образы; последующие используют кэш.

Данные Docker-версии хранятся в постоянном volume `med-calc_postgres_data`. Web, API и PostgreSQL настроены на `restart: unless-stopped`: они запускаются при старте Docker Engine, если не были явно остановлены. Для запуска после входа в Windows включите в Docker Desktop настройку **Start Docker Desktop when you sign in**. Подробности, команды остановки и резервного копирования — в [инструкции Docker](docs/docker.md).

**Для тестирования на удаленном сервере с демонстрационными аккаунтами** используйте `compose.yaml` вместе с `compose.demo.yaml` и файлом `.env.demo` по шаблону `.env.demo.example`. Команда и настройка адреса — в разделе «Тестовый сервер» файла [docs/docker.md](docs/docker.md). Этот вариант сохраняет все четыре demo-аккаунта и позволяет проверить DRAFT-правила.

**Без Docker, для разработки:**

Нужны Node.js **24.21.0** и pnpm **12.8.1**. Из папки проекта:

```powershell
npm install -g pnpm@12.8.1
pnpm install --frozen-lockfile
pnpm db:generate
Copy-Item .env.example .env
pnpm dev
```

Откройте [приложение](http://127.0.0.1:3000). `pnpm dev` проверяет и компилирует данные, затем запускает интерфейс и API. Остановка — Ctrl+C. Установка pnpm не нужна, если он уже доступен.

Для уже подготовленной рабочей папки достаточно `pnpm dev`. Если pnpm не добавлен в PATH, `npm run dev` запускает тот же скрипт при установленных зависимостях.

На Windows также можно открыть `start-demo.cmd` двойным щелчком. После запуска адрес приложения — `http://127.0.0.1:3000`.

| Роль | Логин | Пароль в демонстрации |
|---|---|---|
| Врач | `doctor` | `doctor-demo-2026` |
| Клинический фармаколог | `pharmacist` | `pharmacist-demo-2026` |
| Клинический администратор | `clinical` | `clinical-demo-2026` |
| Системный администратор | `admin` | `admin-demo-2026` |

Эти учетные записи создаются **только** при `DEMO_MODE=true`. В Docker история хранится в PostgreSQL volume. При запуске без Docker и без `DATABASE_URL` история хранится в `.data/local-demo.json`, если скопирован `.env.example`. Не вводите идентификаторы пациентов в свободные комментарии.

## Работа с калькулятором

1. Войти и выбрать нозологию.
2. Указать возраст, затем отвечать на вопросы, которые возвращает сервер. «Неизвестно» сохраняется отдельно от «Нет». Кнопка сохранения результата доступна после завершения расчета.
3. Указать состояние сопутствующей терапии: неизвестна, препаратов нет или известный список. Поиск сохраняет ID из справочника; нераспознанные названия помечаются отдельно.
4. Проверить варианты, ограничения, объяснение и версии. Неполный исходный режим явно требует врачебной проверки.
5. Сохранить результат, скопировать текст, оставить обратную связь. Редактирование черновика не меняет прежний результат.
6. История и CSV/XLSX доступны по правам пользователя. Администратор медицинского контента может импортировать JSON, проверить, опубликовать с подтверждением и эталонными случаями, затем активировать пакет.

## Проверка и сборка

```powershell
pnpm content:compile
pnpm lint
pnpm typecheck
pnpm test
pnpm build
# При запущенном pnpm dev:
pnpm test:e2e
```

На Windows браузерные тесты используют установленный Microsoft Edge. На Linux: `pnpm exec playwright install --with-deps chromium`. Проверяются desktop и tablet. Интеграционные тесты поднимают временный настоящий PostgreSQL на свободном localhost-порту и останавливают его после выполнения; служба ОС не устанавливается. Временные данные остаются в игнорируемой папке `.data/pg-test-*`.

Технические fixtures не являются клинически утвержденными golden cases. В репозитории есть проверки JSON Schema, AST, граничных значений, случайных сочетаний признаков, safety/dose, ролей, lifecycle, сохранности истории, транзакций и браузерного сценария.

| Каталог | Назначение |
|---|---|
| `apps/web` | Next.js, React, TanStack Query, формы и интерфейс на русском |
| `apps/api` | Fastify, Zod, сессии, RBAC, аудит, импорт и экспорт |
| `packages/contracts` | Общие строгие TypeScript-контракты |
| `packages/clinical` | Компилятор, семантический валидатор, AST-интерпретатор, оркестрация и текст рекомендации |
| `packages/therapy` | Разрешение схем, противопоказания, взаимодействия и дозы |
| `packages/db` | Prisma 7, PostgreSQL, миграции и изолированный файловый demo-адаптер |
| `content/source` | Неизмененные данные из предоставленного JSON и извлеченные значения XLSX |
| `content/canonical` | Скомпилированный AST, реестр, выключенные mock и отчет валидации |

| `docs/source` | Копии ТЗ и извлеченный текст контракта |

Клиническое ядро не обращается к БД, сети или окружению. Во frontend отсутствует копия дерева. Preview и сохраненный расчет выполняются одним кодом. Опубликованные пакеты, evaluations, snapshots и аудит защищены от изменения также триггерами PostgreSQL. Сессии серверные, cookie HttpOnly/SameSite, в production Secure; пароли — scrypt, права проверяются сервером, mutation-запросы требуют допустимый Origin.

## PostgreSQL и контейнеры

Для целевого контура задайте `DEMO_MODE=false`, `DATABASE_URL`, `APP_ORIGIN` с HTTPS, `BOOTSTRAP_ADMIN_LOGIN` и уникальный `BOOTSTRAP_ADMIN_PASSWORD` длиной не менее 16 символов. Выполните `pnpm db:migrate`, затем запустите API и web. Первичный администратор создает клинического администратора; тот импортирует, валидирует, утверждает и активирует медицинский пакет. До этого клинические расчеты возвращают `CONTENT_PACKAGE_NOT_PUBLISHED`.

`compose.yaml` поднимает локальную демонстрацию с PostgreSQL, миграциями, API и собранным web. Наружу опубликован только web на loopback-порту 8080; API и база доступны внутри сети Compose. Для целевого контура используйте дополнительно `compose.production.yaml`: у него отдельное имя проекта и volume, отключены demo-учетные записи, обязательны HTTPS origin и пароль администратора. HTTPS termination и резервное копирование настраиваются инфраструктурой перед пилотом. В Docker `API_URL` задается при сборке; для другого адреса используйте build-arg `API_URL`. Точные команды — в `docs/docker.md`.

Файловый адаптер запрещен в production. Репозиторий PostgreSQL рассчитан на небольшой пилот: транзакции сериализуются advisory lock, данные загружаются в память. Перед ростом нагрузки нужны адресные запросы и пагинация; целевая p95 под пользовательской нагрузкой отдельно не измерялась.

## Медицинские данные и согласования

В `docs/content-decisions.md` перечислены технические нормализации и обнаруженные расхождения исходников. Программа не дополняет клинические правила внешними медицинскими рекомендациями и не придумывает формулы коррекции доз. Публикация требует результатов golden cases и записи человеческого подтверждения; автоматические тесты не заменяют эту приемку.

Проект проверен локально; внешнее размещение и клиническая публикация не выполнялись.
