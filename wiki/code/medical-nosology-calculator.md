# Медицинский калькулятор нозологий 0.1.0

## Назначение

Поддержка врачебного решения по шести нозологиям на основании предоставленных правил. Медицинские пакеты DRAFT доступны только при `DEMO_MODE=true`; клиническая публикация требует человеческого утверждения. Оформление и общие подписи обновлены в [[code/clinical-paper-interface]].

## Алгоритм

Валидация фактов → AST и баллы → клиническая схема/терминал → лекарственные варианты → противопоказания и взаимодействия → базовый либо валидированный скорректированный режим → структурированный результат, объяснение, неизменный снимок и трассировка.

## Параметры и конфигурация

| Параметр | Значение | Описание |
|---|---|---|
| ruleset | 0.1.0 | 6 нозологий, 133 узла, 148 переходов |
| facts | 75 | Типизированные клинические признаки |
| treatment options | 184 | Отдельные варианты препаратов |
| max_steps | 100 | Ограничение обхода |
| storage | PostgreSQL 18.4 / локальный demo | Docker использует постоянный PostgreSQL volume |
| Docker web | localhost:8080 | Автозапуск сервисов при запуске Docker Engine |
| Production origin | `APP_ORIGIN=https://ваш-домен` | Точный внешний origin без завершающего `/`; задается в `.env.production` |
| Production HTTPS | Nginx → `http://127.0.0.1:8080` | Nginx на хосте завершает TLS; production session-cookie имеет флаг Secure |

Для production используется сочетание `compose.yaml` и `compose.production.yaml`. HTTPS настраивается отдельно на сервере; наличие этих параметров в документации не означает, что удаленное развертывание выполнено. Подробности запуска — `docs/docker.md`, требования к сессиям и Origin — `apps/api/README.md`.

## Анализ сложности

Текущий обход фильтрует ребра на каждом посещенном узле: O(H·E + A), где H — длина пути, E — число ребер, A — объем вычисленных AST/баллов. Хэширование пакета — O(P), P — размер canonical JSON. Семантическая проверка перебирает репрезентативные комбинации входов каждого узла, ограничивая их число 20 000. При росте набора правил полезно индексировать исходящие ребра; для текущего пакета приоритет имеет проверяемость.

## Результаты и наблюдения

Обновление тестового сервера автор выполняет самостоятельно после получения кода из GitHub. Инструкция `docs/update-test-server.md` сохраняет существующую базу и обновляет только API/web; включает резервную копию, проверку истории/отзывов и откат образа.

27.10.2026 исправлен интерфейс по замечаниям врачей: автосохранение, групповой ввод, возврат и отмена, пояснение неизвестных данных, сворачиваемая сопутствующая терапия, устранение повторов и отзыв непосредственно к показанному результату. Опечатки исправляются при отображении/копировании, без правки медицинских пакетов. Для публикации отдельно проверен набор: 151 тест Vitest и типы; интерфейс ранее прошёл 32 браузерные проверки и сборку. Подробности — [[code/medical-feedback-and-interactions]], вопросы медикам — [[writing/medical-questions]].

Проверки охватывают границы, UNKNOWN, AST, графы, привязку МНН к ID, safety/dose, API, роли, историю, PostgreSQL и браузер. Найденные расхождения источников и технические нормализации записаны в `docs/content-decisions.md`. Клинически утвержденные golden cases не предоставлены.

Исходная версия до этих изменений прошла 147 автоматических проверок. Docker-сервисы проходят healthcheck; пересоздание контейнеров сохраняет сессию и снимок результата. Подробный протокол — `docs/validation-report.md`, запуск и резервные копии — `docs/docker.md`.
