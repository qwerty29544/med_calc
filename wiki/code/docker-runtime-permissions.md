# Исправление прав доступа к коду в Docker

## Назначение

Устранить перезапуск API с `EACCES: permission denied, open '/app/apps/api/src/app.ts'` после обновления [[code/clinical-paper-interface]]. В присланном серверном выводе PostgreSQL оставался `healthy`; перед обновлением были видны 16 расчётов и 0 отзывов. Эти сведения не заменяют проверку истории после восстановления приложения.

## Алгоритм

Dockerfile копировал код с владельцем `root`, затем запускал процесс от `node`. При правах исходников `600` и родительских каталогов `700` пользователь `node` не мог прочитать `app.ts`. Сбой воспроизведён в отдельном Linux-образе с такими правами, включая тот же путь и код `EACCES`.

Копирование изменено на `COPY --chown=node:node . .`. Код и исходные каталоги становятся доступны владельцу `node`; `USER node` сохранён. Сборка Prisma, компиляция медицинского контента и production-сборка выполняются как прежде. Клинические правила, API, схема БД и Compose не менялись.

В ранее выданном объединённом блоке `umask 077` действовал также во время `git pull`; это могло создавать новые файлы с ограниченными правами. Точные права серверных файлов отдельно не снимались, поэтому конкретный источник их режима не установлен. В инструкции `git pull` получает локальный `umask 022`, а `077` применяется только в подпроцессе резервного копирования. Исправление владельца внутри образа работает и для уже существующих файлов `600`.

## Параметры и конфигурация

| Параметр | Значение | Описание |
|---|---|---|
| Пользователь процесса | `node`, UID 1000 | Непривилегированный запуск сохранён |
| Владелец скопированного кода | `node:node` | Явно задан в Dockerfile |
| Права тестового контекста | файлы `600`, каталоги `700`, владелец `root` | Воспроизводят отказ прежнего образа |
| Получение кода | отдельный `umask 022` | Не наследует ограничение резервного копирования |
| Резервная копия | отдельный `umask 077` | Ограничение действует только внутри backup-блока |
| Восстановление приложения | `up --no-deps --no-build --force-recreate api web` | Прежний проект и PostgreSQL volume сохранены |

## Анализ сложности

Клинические вычисления не меняются. Назначение владельца применяется при прежнем копировании файлов в образ; дополнительная рекурсивная обработка каталогов во время запуска приложения не добавлена.

## Результаты и наблюдения

- **RED:** полный исходный Dockerfile собран с ограниченными правами tar-контекста; чтение `app.ts` от runtime-пользователя завершилось с тем же `EACCES` и кодом 1.
- **GREEN:** исправленный Dockerfile собран из такого же контекста; UID 1000 прочитал `app.ts`, `server.ts`, контракт и canonical rules, код 0.
- **Запуск:** отдельные временные контейнеры без volumes, опубликованных портов и внешней сети вернули HTTP 200 для `/api/v1/health` и `/login`. API использовал временное локальное хранилище в `/tmp`; серверный PostgreSQL не подключался.
- **Регрессия:** 153/153 теста опубликованного набора прошли. Production-сборка прошла в Linux-образе с исправлением.

На удалённом сервере исправление ещё не проверено. Для применения, чтения кода до запуска, сравнения количества расчётов и проверки старых результатов используется раздел восстановления в `docs/update-test-server.md`. Автоматическое восстановление дампа не выполняется: оно может заменить более новые записи.
