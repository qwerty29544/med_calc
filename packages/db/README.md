# Persistence

Основной адаптер: PostgreSQL и Prisma 7 с `@prisma/adapter-pg`. `pnpm db:generate` создает клиент, `pnpm db:migrate` применяет SQL миграции. Для Docker используйте отдельный persistent volume PostgreSQL. Не выдавайте runtime-подключению superuser или права изменения схемы; учетная запись миграций должна быть отдельной.

Таблицы содержат реляционные идентификаторы, внешние ключи и индексы по владельцам/версиям, а версионируемые структуры — JSONB. Транзакция изменения черновика записывает редакцию и аудит вместе; расчет сохраняет snapshot и результат вместе. SQL triggers запрещают UPDATE/DELETE расчетов, редакций, feedback, активаций и audit; опубликованные пакеты также неизменяемы. Активация ссылается только на опубликованный пакет соответствующего типа.

Записи API сериализуются транзакционным advisory lock; независимые чтения получают snapshot Repeatable Read. Это консервативный адаптер версии 0.1.0: он загружает состояние таблиц и сравнивает изменения в приложении. При росте истории необходим переход к адресным запросам repository, постраничным спискам и потоковому экспорту. Производительность на больших клинических наборах текущим адаптером не заявляется.

Файловый `DemoStore` предназначен для локального запуска одного процесса. Он проверяет явный demo-режим, запрещен в production, удерживает process lock, сериализует транзакции, пишет временный файл с fsync и атомарно заменяет основной файл. Ошибки откатывают весь набор изменений. Копия возвращаемого состояния не позволяет обойти транзакцию.

Проверки: `tests/db.test.ts` — durable reopen, конкурентные транзакции, rollback и immutable audit; `tests/api.test.ts` — история, права, публикация и совместимые наборы; `tests/postgres.integration.test.ts` — настоящая временная PostgreSQL, миграция, snapshots, rollback и запрет прямого изменения immutable таблиц.
