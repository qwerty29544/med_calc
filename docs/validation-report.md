# Техническая проверка 0.1.0

Дата: 2026-10-03. Среда: Windows, Node.js 24.21.0, Docker Desktop 4.93.0, Linux-контейнеры, PostgreSQL 18.4.

## Проверенные свойства

- `pnpm lint`: форматирование исходников проходит.
- `pnpm typecheck`: strict TypeScript проходит.
- `pnpm content:compile`: 6 нозологий, 75 фактов, 133 узла, 148 переходов, 53 схемы, 184 отдельных лекарственных варианта. Canonical SHA-256: `4348fd9f1f1ef478c10a78489e9cdbef5d7b002ae7a3d1a419a5ddb42c9fc65d`.
- `pnpm test`: **147/147** проверок в 9 файлах, включая 4 интеграционные проверки с настоящим PostgreSQL. Проверены UNKNOWN, границы, детерминизм, валидация AST/графа, safety/dose, RBAC, публикации и атомарная активация, rollback и запрет изменения сохраненных результатов SQL-триггерами.
- Linux Docker build: Prisma Client генерируется, canonical content компилируется, Next.js production-сборка проходит.
- Docker: миграции применяются автоматически, web/API/PostgreSQL проходят healthcheck. Web опубликован на loopback-порту 8080, база и API остаются во внутренней сети.
- `node scripts/check-docker.mjs`: создан технический случай, сохранен результат, затем полностью пересозданы контейнеры. Сессия и полный неизменяемый результат совпали с сохраненными до пересоздания; хранилище — PostgreSQL, volume сохранен.
- `BASE_URL=http://127.0.0.1:8080 pnpm test:e2e`: **18/18**, exit code 0, 51,5 секунды. Desktop и tablet в Microsoft Edge; проверены все шесть нозологий, история, feedback, роли, UNKNOWN, гонка preview и отображение доз. Полный вывод — `docs/verification/e2e-docker-final.txt`, снимки — `docs/screenshots/`.
- Резервное копирование: `pg_dump -Fc` успешно создал архив текущей demo-БД; `pg_restore --list` прочитал его оглавление. Восстановление из архива не выполнялось.

## Дополнение: демонстрация на тестовом сервере

Проверена конфигурация `compose.yaml` + `compose.demo.yaml` в отдельном временном проекте `med-calc-demo-verify`. PostgreSQL, API и web прошли healthcheck; вход подтвержден для `doctor`, `pharmacist`, `clinical`, `admin` с соответствующими ролями. Врач выполнил и сохранил DRAFT-расчет. Проверены demo-подсказки на странице входа, разрешенный внешний Origin и отказ чужому Origin (403). Удаленный сервер в этой проверке не использовался; конфигурация исполнялась локально в Docker. Временное проверочное окружение удалено после проверки.

## Производительность

`node --import tsx scripts/benchmark.ts`: 100 повторных запусков прогретого клинического ядра для случая CB_S1_R1, включая хэширование и trace: p50 ≈ 5,13 мс, p95 ≈ 5,74 мс, максимум ≈ 6,54 мс. Это локальный микробенчмарк ядра; он не измеряет задержки сети, PostgreSQL или многопользовательскую нагрузку.

## Границы проверки

Медицинская приемка не выполнялась: утвержденные экспертами golden cases не приложены. Исходные медицинские пакеты сохраняют статус DRAFT, mock safety/dose-правила выключены. Технические fixtures не считаются клиническим утверждением. Не проверялись внешнее размещение, HTTPS proxy, восстановление production-базы, браузер Safari на физическом iPad и нагрузка нескольких пользователей. Адаптер PostgreSQL рассчитан на небольшой пилот; масштабирование требует адресных запросов и пагинации.
