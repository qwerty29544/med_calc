# Реализация медицинского калькулятора 0.1.0

Основание: `source/TZ_02_System_Technical_Spec_v0.1.0.md`, `source/contract.txt` и предоставленные авторские таблицы. Запрос автора прямо разрешает реализацию по этой спецификации.

## Архитектура и ограничения

Модульный монолит: Next.js / React, Fastify, чистое TypeScript-ядро, PostgreSQL. Клиническое дерево исполняется исключительно сервером из canonical AST. Неизвестные данные не равны отрицательному ответу. Пакеты DRAFT доступны только в явно обозначенном демонстрационном режиме; публикация требует подтверждения медицинского администратора и эталонных случаев. Mock safety-правила выключены. Дозы не исправляются по внешним медицинским знаниям.

## Этапы и проверки

- [x] Клинический контракт, компилятор и ядро: JSON Schema, белый список AST, типы/единицы, трехзначная логика, баллы, циклы/ссылки/ветви, все шесть нозологий. Сначала тесты `tests/domain.test.ts`, затем `packages/clinical`.
- [x] Терапия, безопасность и дозирование: структурированные варианты, сохранение источников, приоритет BLOCK > REVIEW_REQUIRED > WARN > ALLOW, неполнота проверок, fallback базового режима. Проверки независимыми fixtures без признания их клинически утвержденными.
- [x] Сервер и хранение: Fastify API, сессии, RBAC, черновики, immutable snapshots, транзакции, история, feedback, CSV/XLSX, lifecycle пакетов и аудит. Тесты на отказ чужому пользователю, изменение истории, публикацию DRAFT и некорректные данные.
- [x] Интерфейс: вход, выбор нозологии, последовательные вопросы сервера, сопутствующие препараты, результат, копирование, история, обратная связь, администрирование. Русский язык; desktop/tablet; состояния загрузки и ошибок.
- [x] Интеграция: strict typecheck, все тесты, компиляция исходных данных, production build, браузерная проверка, инструкция запуска и Docker Compose.

## Особое внимание

Точные границы 65/80 лет, WBC 12, нейтрофилы 5.5, палочкоядерные 10, CRP 50; UNKNOWN внутри AND/OR; устаревший ответ асинхронного preview; ограничения доступа к чужим случаям; сохранность публикаций/снимков; неоднозначные исходные дозировки.

## Решения

Рабочая папка изначально пуста и не является git-репозиторием. Входные файлы сохранены копиями в `content/source` и `docs/source`; оригиналы не изменяются. В ходе реализации пользователь установил Docker и запросил полный контейнерный запуск. Основной удобный запуск — Compose с PostgreSQL, постоянным volume, автоматическими миграциями и перезапуском сервисов. Для разработки остается явно отмеченный файловый demo-адаптер. Клиническая приемка и утвержденные медицинской командой golden cases не подменяются техническими тестами.
